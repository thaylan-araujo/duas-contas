    **schema.ts** — Zod schemas only, no server code:
    - transactionSchema: object with date (string min 1), description (string min 1 max 120), amountCents (number int positive), type (enum ENTRADA|SAIDA), account (enum CASA|EMPRESA), categoryId (string min 1), notes (string optional max 200).
    - Export TransactionFormData as z.infer of transactionSchema.

    **service.ts** — pure TypeScript business logic, no 'use server', imports prisma from '@/lib/prisma':
    - getCategories(userId: string): returns prisma.category.findMany where userId, ordered by name.
    - createTransactionService(data: TransactionFormData & { userId: string }): prisma.transaction.create. Store amountCents as Int. Date: use parseISO from date-fns to convert "YYYY-MM-DD" string to Date object (never new Date() on the string directly — prevents timezone drift).

    - deleteTransactionService(id: string, userId: string): findFirst with { id, userId }. If null throw "Lançamento não encontrado.". If record.pairId is not null throw "PAIRED_TRANSACTION". Otherwise prisma.transaction.delete where { id }.

    **loader.ts** — server-side data loading utilities, imports prisma from '@/lib/prisma':
    - getTransactions(userId: string, month: string, account?: string): parse month "YYYY-MM" with split('-') into year/monthNum. Build start = new Date(year, monthNum-1, 1) and end = new Date(year, monthNum, 0). Prisma findMany where userId, date gte start lte end, account if provided (cast to ContaType). Include { category: true }. OrderBy date desc.
    - getCategories(userId: string): same as in service.ts — DRY import from service or duplicate as needed.

    **actions.ts** — 'use server' thin actions, each reads userId from session via createSupabaseServerClient (never from form input — security rule), calls service, calls revalidatePath:
    - createTransactionAction(_prev: unknown, data: TransactionFormData): parse with transactionSchema.safeParse, get userId from session, call createTransactionService, revalidatePath('/lancamentos'), return { success: true } or { success: false, error: string }.
    - updateTransactionAction(_prev: unknown, data: z.infer<typeof updateTransactionSchema>): same pattern — parse with updateTransactionSchema, userId from session, call updateTransactionService, revalidatePath('/lancamentos').
    - deleteTransactionAction(id: string): userId from session, call deleteTransactionService, revalidatePath('/lancamentos') and revalidatePath('/visao-geral'). Handle PAIRED_TRANSACTION error by returning { success: false, error: 'PAIRED_TRANSACTION' } — the client uses this to open the pró-labore delete Dialog.
    - Error messages: network/unknown errors return "Não foi possível salvar. Verifique sua conexão e tente novamente." in Portuguese.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form → Server Action | User submits transaction data |
| Server Action → Prisma service | Mutation with userId from session |
| Server Component → Prisma | Read queries with userId filter |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Elevation of Privilege | service.ts — all Prisma queries | mitigate | Every query includes `where: { userId }` from session; userId never from form data |
| T-02-05 | Tampering | amountCents in transactionSchema | mitigate | Zod: z.number().int().positive() — rejects negative values, floats, and zero |
| T-02-06 | Tampering | mass assignment in Server Action | mitigate | transactionSchema.safeParse whitelist — only declared fields parsed; extras ignored |
| T-02-07 | Spoofing | CSRF on Server Actions | accept | Next.js Server Actions enforce same-origin by default; no additional CSRF token needed |
| T-02-08 | Tampering | pairId bypass — editing paired transaction | mitigate | service.ts checks pairId !== null and throws PAIRED_TRANSACTION; action surfaces this to UI |
| T-02-SC | Tampering | npm/npx installs | mitigate | No new packages in this plan — uses packages from Plan 01 |
</threat_model>
