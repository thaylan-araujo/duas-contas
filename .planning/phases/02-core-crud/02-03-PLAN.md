## Phase Goal

**As a** user, **I want to** register pró-labore transfers and manage custom categories, **so that** I can track the only allowed money flow between Casa and Empresa and keep my category list accurate.

<objective>
Extend the transaction CRUD slice with two features: (1) pró-labore — an atomic dual-record operation that creates a SAIDA on Empresa and an ENTRADA on Casa with the same pairId, (2) category management — inline creation in the form Select plus a full Gerenciar Categorias Sheet with edit/delete guards.

Purpose: Fulfils the inviolable business rule that money only crosses accounts via explicit pró-labore, plus gives users control over their category taxonomy.
Output: TransactionSheet updated with pró-labore type, ManageCategoriesSheet component, category CRUD Server Actions, pró-labore Server Actions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Server Action (pró-labore) | User submits pró-labore data |
| Server Action → prisma.$transaction | Atomic dual-record creation |
| Browser → Server Action (category delete) | User requests category deletion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Tampering | createProLaboreService — partial failure | mitigate | prisma.$transaction interactive mode: both records created or neither; rollback is automatic on any error |
| T-02-10 | Elevation of Privilege | deleteProLaboreService | mitigate | deleteMany includes userId filter — user can only delete their own pró-labore pairs |
| T-02-11 | Tampering | category delete with linked transactions | mitigate | deleteCategoryService counts linked transactions and throws if count > 0; never cascades deletion (D-08) |
| T-02-12 | Tampering | editando categoria padrão | mitigate | updateCategoryService checks isDefault: true and throws; frontend also hides edit buttons |
| T-02-13 | Elevation of Privilege | category CRUD — accessing another user's categories | mitigate | updateCategoryService and deleteCategoryService include userId in findFirst where clause |
| T-02-SC | Tampering | npm/npx installs | mitigate | No new packages in this plan |
</threat_model>
