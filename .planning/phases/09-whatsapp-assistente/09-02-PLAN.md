<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Evolution API (internet) → POST /api/whatsapp/webhook | Payload não-confiável cruza aqui; autenticação do canal = segredo + allowlist |
| Texto da mensagem → Claude Haiku | Conteúdo controlado pelo remetente chega ao LLM |
| Handler → createTransactionService | Escrita no banco com o userId resolvido pela allowlist |
| Handler → Evolution REST (sendText) | Saída para o número do remetente |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Spoofing | Webhook POST (payload forjado por terceiro) | mitigate | `verifyWebhookSecret` com `crypto.timingSafeEqual` (constant-time, nunca `===`) + allowlist de número (`resolveContact` ativo); rejeição responde 200 `{ignored}` sem revelar o motivo |
| T-09-02 | Tampering/DoS | Reentrega/replay da Evolution → lançamento duplicado | mitigate | `dedupeInbound` insere `WhatsappInbound` ANTES de lançar; `@@unique(messageId)` → P2002 → 200 sem relançar; handler sempre responde 200 para não disparar retry |
| T-09-03 | DoS | Loop de eco (`fromMe:true`) e mensagens de grupo | mitigate | `parseInbound` detecta `fromMe`/`isGroup`; handler retorna 200 ANTES de chamar o LLM (economiza custo e evita loop) |
| T-09-04 | Information Disclosure | Vazar finanças a número não autorizado | mitigate | Número fora da allowlist nunca é processado nem recebe dados (resolveContact null → 200 ignore); nenhuma resposta com dado financeiro a desconhecido |
| T-09-05 | Elevation of Privilege | IDOR cross-user (empresa/categoria de outro usuário) | mitigate | `getEmpresas`/`getCategories` filtram por `userId`; `createTransactionService` grava com o `userId` da allowlist; destino/categoria resolvidos só dentro do contexto carregado desse userId |
| T-09-06 | Tampering | Prompt injection no texto reaching LLM/DB | mitigate | A IA só preenche um tool com enums/tipos fixos; resultado re-validado por `aiResultSchema` (Zod) e pelo `transactionSchema`; a regra Casa×Empresa é CÓDIGO (resolveDestino/resolveCategoria), o LLM nunca decide o `empresaId`/`categoryId` final (só sugere nomes que o código resolve) |
| T-09-07 | Information Disclosure | Segredo/API key em log | mitigate | Segredos só em env var (process.env); não logar body cru com dados financeiros nem o segredo; erro capturado loga mensagem genérica |
</threat_model>
