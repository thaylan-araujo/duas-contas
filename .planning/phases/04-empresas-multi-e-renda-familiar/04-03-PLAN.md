<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cliente → Server Action | nome/tipo/cor da empresa e empresaId/kind da categoria vêm do cliente |
| Server Action → DB | criar/editar/excluir empresa e categorias |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Elevation of Privilege (IDOR) | criar categoria/lançamento com `empresaId` de outro usuário | mitigate | Service valida `empresa` pertence ao userId (`findFirst({ where: { id: empresaId, userId } })`) antes de escrever; todas as queries incluem `where: { userId }` (ASVS V4) |
| T-04-07 | Tampering | mass assignment via Server Action de empresa | mitigate | `empresaSchema.safeParse` (nome<=60, tipo no enum, cor na paleta) + userId sempre da sessão (getUserId), nunca do input |
| T-04-08 | Tampering / Data loss | excluir empresa com lançamentos | mitigate | `deleteEmpresaService` conta lançamentos e bloqueia (D-08); FK `ON DELETE RESTRICT`; exclusão de categorias+empresa em `prisma.$transaction` |
| T-04-09 | Spoofing | userId vindo do input | mitigate | `getUserId()` lê `supabase.auth.getUser()` — nunca do form (padrão canônico Fase 2/3) |
</threat_model>
