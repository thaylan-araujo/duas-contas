## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cliente (store/URL) → Server Component | `empresaId` do contexto vem do searchParam controlado pelo cliente |
| Server Component → DB | queries de lançamentos/dashboard filtradas por empresaId |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Elevation of Privilege (IDOR) | `?empresaId=` forjado para ver/gravar em empresa de outro usuário | mitigate | Todas as queries de lançamento/dashboard incluem `where: { userId }` (sessão); criar lançamento valida que `empresaId` pertence ao userId antes de gravar (reforço do Plano 03); empresaId inexistente/alheio -> sem resultados |
| T-04-11 | Tampering | lançar na empresa errada via contexto adulterado | mitigate | `empresaId` gravado = contexto validado; FK garante que só empresaId existente é aceito; Casa = null explícito |
| T-04-12 | Information Disclosure | contexto apontando para empresa excluída | accept | Fallback para Casa no ContaSelector/loader; risco baixo (sem vazamento — queries por userId retornam vazio) |
</threat_model>
