<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /login | Credenciais de login (email + senha) trafegam via HTTPS |
| Cookie de sessão → middleware | Cookie httpOnly validado server-side a cada request protegido |
| Usuário autenticado → rotas protegidas | Middleware bloqueia acesso sem sessão válida |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | middleware.ts — getUser() vs getSession() | mitigate | getUser() valida JWT com o servidor Supabase Auth a cada request; getSession() lê cookie sem verificação e permite sessão forjada (ASVS V2.1). NÃO usar getSession() em nenhum lugar. |
| T-02-02 | Information Disclosure | LoginForm — mensagem de erro | mitigate | Erro de credenciais inválidas usa mensagem genérica "E-mail ou senha incorretos" — NÃO diferencia "email não existe" de "senha errada" para não expor se o email está cadastrado (ASVS V2.2) |
| T-02-03 | Elevation of Privilege | /(authed)/* — acesso sem autenticação | mitigate | Middleware intercepta toda rota fora de /login antes do rendering; redirect para /login antes de qualquer Server Component executar (ASVS V4.1) |
| T-02-04 | Tampering | Session cookie | accept | Supabase SSR configura cookies como httpOnly, Secure, SameSite=Lax automaticamente; não é necessário configuração manual (ASVS V3.1) |
| T-02-05 | Denial of Service | Supabase free tier auto-pause | mitigate | GitHub Actions keep-alive cron job (a cada 3 dias) previne pausa de 7 dias por inatividade |
| T-02-SC | Tampering | npm install — supply chain | mitigate | Dependências deste plano (lucide-react via shadcn) auditadas no Package Legitimacy Audit de RESEARCH.md; sem novos pacotes |
</threat_model>
